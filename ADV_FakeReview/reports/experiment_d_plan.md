# 실험 D (종료 - 실현 불가 확인): 실제 사람이 쓴 가짜 리뷰 + 실제 이미지 데이터셋 직접 구축 시도

## 왜 시도했나

실험 A(AiGen-FoodReview)와 실험 C(Ott)를 비교해보니, 같은 파이프라인인데도
"가짜의 정체"에 따라 성능이 크게 갈렸다(acc 0.997 vs 0.879). 그런데 실험 C(Ott)는
텍스트만 있어서, "사람이 쓴 진짜로 어려운 가짜 리뷰"를 이미지까지 포함해서
검증한 적은 아직 없다. "이미지 + 텍스트가 둘 다 있으면서 + 가짜가 LLM 대필이
아니라 실제 상황에서 나온 가짜"인 데이터셋을 찾아봤는데, 공개된 형태로는 존재하지
않는다는 걸 확인했다(AiGen-FoodReview 논문 저자들이 이 데이터셋을 만든 이유 자체가
이 갭 때문이었음).

## 시도한 접근: 두 데이터셋을 조인해서 직접 만들기

기성 데이터셋이 없으니, 서로 다른 목적으로 만들어진 두 공개 데이터셋을 조인해보려
했다.

| | 내용 | 이미지 | 가짜 라벨 |
|---|---|---|---|
| Hollenbeck et al. `fake-reviews-data` | Amazon 가짜 리뷰 언더그라운드 마켓 추적 + Amazon 자체 리뷰 삭제 데이터를 결합해 만든 라벨 | 없음 | 있음 (실제 상황 기반) |
| McAuley Lab Amazon Reviews 2023 (Health_and_Personal_Care) | 리뷰 텍스트 + 리뷰어 ID + 시각 | 있음 (실사용자 업로드 사진) | 없음 |

asin(상품 ID) 기준으로 두 데이터를 조인해서, "실제 가짜 라벨이 있으면서 + 실제
사진도 있는" 교집합 리뷰만 뽑아내는 게 목표였다.

## 결론: 조인 불가능 (스키마 확인 결과)

`python src/build_amazon_hard_dataset.py --explore`를 학교 서버에서 실행해서 실제
스키마를 확인한 결과, **이 조인은 애초에 불가능하다는 게 확인됐다.**

Hollenbeck 데이터셋(`final-dataset-all.dta`, 314,330행 × 33컬럼)은 개별 리뷰 단위
데이터가 아니라 **"상품 × 주(week)" 단위로 집계된 패널 데이터**였다. 컬럼 구성
(`interval_st`, `interval_lt`, `time_week`, `num_reviews`, `avg_rating`,
`have_fake_reviews`, `is_focal`, `sales_rank`, `id`, `catid` 등)을 보면, 가짜 리뷰
캠페인 전후로 판매 순위/가격/평점이 어떻게 바뀌는지를 분석하기 위한 event-study용
경제학 연구 데이터로 설계된 것이다. 구체적으로:

- `id`는 실제 Amazon 상품 ID(ASIN)가 아니라 연구자가 내부적으로 붙인 정수 인덱스
- `product_category`는 개별 상품이 아니라 "Pet Supplies", "Tools & Home
  Improvement" 같은 91개 대분류 값
- **실제 ASIN(상품 고유 식별자) 컬럼 자체가 존재하지 않음**

즉 `have_fake_reviews=1`인 상품이 69,319건(상품-주 관측치 기준) 있다는 건 알 수
있어도, 그게 정확히 어느 상품(ASIN)인지는 이 데이터만으로 알 수 없다. Amazon
Reviews 2023의 리뷰/이미지와 연결할 공통 키가 없어서, 계획했던 조인은 실행
자체가 불가능하다.

이건 실행상의 실수가 아니라, 이 데이터가 원 논문(인과추론/이벤트 스터디)의
목적에 맞게 개인정보·저작권 이슈를 피해 집계된 형태로만 공개된 것으로 보인다.
"리뷰 단위로 실제 가짜 라벨 + 실제 이미지가 둘 다 있는" 공개 데이터가 없다는
최초 판단이 다시 한번 확인된 셈이다.

## 발표에서 어떻게 쓸지

이 시도 자체를 "실패"가 아니라 "조사 과정"으로 정리하면 된다:

1. 실험 A/B/C(난이도 스펙트럼: 쉬움-보통-어려움)만으로 발표는 충분히 완결된다.
   이 실험은 처음부터 성공하면 보너스, 실패해도 기존 결과에 영향 없는 애드온으로
   설계했다.
2. "왜 3-modality(텍스트+이미지+행동)를 동시에 실증하지 못했는가"라는 질문에,
   "실제로 대안 데이터셋 구축을 시도했고, 어떤 데이터가 어떤 이유로 부적합한지
   구체적으로 확인했다"는 근거를 댈 수 있다 (Hollenbeck 데이터는 집계 패널이라
   리뷰 단위 연결이 불가능함을 실제 스키마 분석으로 확인).
3. 향후 연구 슬라이드에: "리뷰 단위 실제 가짜 라벨 + 실제 이미지가 함께 있는
   데이터셋 구축(직접 라벨링 또는 연구자 접촉을 통한 원 데이터 요청)"을 다음
   단계로 제시.

## 시도한 코드 (참고용, 실행 안 함)

`scripts/download_amazon_hard.sh`, `src/build_amazon_hard_dataset.py`는 이 조사
과정의 기록으로 리포에 남겨둔다. `--explore` 모드까지는 정상 동작했고, 실제
조인(`build()`)은 위 결론에 따라 구현하지 않았다(스키마상 불가능하므로 의미
없음).
