# 실험 B 결측 modality 처리: v1 → v2 → v3 전체 정리

MPLMM(Missing-modality Prompt Learning) 아이디어를 실험 B(YelpChi)에 적용해보면서,
"결측 정보를 어떻게 보완할지"를 세 단계로 점점 더 정교하게 만들어봤다. 각 단계에서
왜 안 됐는지/왜 됐는지를 구조적으로 설명할 수 있어서, 결과 자체보다 이 과정이
더 의미있는 실험이 됐다.

## 시나리오 (공통)

YelpChi 전체 45,954개 노드 중 20%(9,190개)를 "리뷰 이력이 거의 없는 신규 유저"
(behavior/그래프 modality가 사실상 결측된 상황)로 인위 지정. 세 버전 모두 같은
seed, 같은 결측 마스크를 사용해서 공정 비교했다.

## 세 가지 시도

| 버전 | 결측 처리 방식 | 프롬프트가 심어지는 위치 |
|---|---|---|
| v1 | 결측 노드의 최종 graph representation을 학습된 상수 벡터로 대체 | GNN이 계산을 **다 끝낸 뒤**, 분류기 바로 앞 |
| v2 | 결측 노드의 원본 feature를 0으로 지우고, 학습된 상수 벡터를 flag 채널로 concat | GNN **입력 단** (2개 layer의 ReLU + 이웃 aggregation을 통과) |
| v3 | v2와 동일한 위치지만, flag를 고정 상수가 아니라 `feat_repr`(리뷰 자체 정보, 결측 영향 안 받음)로부터 작은 MLP가 노드마다 다르게 생성 | GNN 입력 단, **노드별로 다른** conditional prompt |

## 결과 (결측으로 시뮬레이션된 노드만 기준 - 효과가 가장 뚜렷하게 보이는 부분)

| 세팅 | acc | f1 | auc |
|---|---|---|---|
| (1) reference (결측 없음, ceiling) | 0.9089† | 0.7508† | 0.9451† |
| (2) naive (0으로 채움/지움) | 0.8403 | 0.6147 | 0.9041 |
| (3) v2: static prompt (모든 결측 노드 동일 벡터) | 0.8473 | 0.6154 | 0.9009 |
| (4) v3: conditional prompt (노드별로 다르게 생성) | 0.8496 | 0.6234 | 0.9101 |

† v1 실험의 ceiling 수치. v2/v3는 아키텍처가 약간 달라(입력에 prompt_dim=8 채널
추가) ceiling이 근소하게 다르지만(f1 0.6897), 세팅 간 상대적 비교에는 영향 없음.

## 해석: 왜 점점 나아졌나

**naive → v2 (static prompt)**: 개선폭이 매우 작았다(f1 +0.0007). 이유는 v1에서
이미 확인한 문제(대체값이 선형 분류기 직전에서 편향으로 흡수됨)는 고쳤지만,
"모든 결측 노드에 완전히 동일한 벡터"를 쓰다 보니 모델이 배울 수 있는 건 "결측
여부"라는 이진 신호 하나뿐이었다. 이건 사실상 결측 여부를 나타내는 상수 하나를
추가한 것과 비슷해서, 여전히 개선 여지가 제한적이었다.

**v2 → v3 (conditional prompt)**: 개선폭이 뚜렷하게 커졌다(f1 +0.0080, naive 대비
+0.0087, acc/auc 모두 v2보다 개선). 결측 노드마다 갖고 있는 다른 정보(`feat_repr`,
즉 이 리뷰 자체의 텍스트/평점 등)를 보고 prompt를 다르게 생성하게 하니까, "결측
여부"뿐 아니라 "이 노드는 이런 특징이 있으니 이렇게 보완하자"는 노드별 맞춤
보완이 가능해진 것으로 보인다.

**naive 대비 ceiling까지의 격차를 얼마나 좁혔는가**로 보면 더 명확하다:

```
ceiling(0.7508) - naive(0.6147) = 0.1361  (전체 격차)
v2가 좁힌 정도: 0.6154 - 0.6147 = 0.0007   (격차의 0.5%)
v3가 좁힌 정도: 0.6234 - 0.6147 = 0.0087   (격차의 6.4%)
```

절대적인 수치로는 크지 않지만(여전히 ceiling과는 거리가 있음), **"위치를
고치는 것"보다 "조건부로 만드는 것"이 훨씬 더 큰 기여를 했다**는 방향성은
뚜렷하다. v2 대비 v3의 개선폭이 v1 대비 v2의 개선폭보다 10배 이상 크다.

## 종합 결론 (발표에 쓸 메시지)

세 단계를 거치며 얻은 일반화 가능한 교훈:

1. **결측 정보를 어디서 보완하느냐가 중요하다** — 최종 분류기 직전이 아니라,
   비선형 변환(그리고 가능하면 그래프 전파처럼 다른 노드에도 영향을 주는 경로)을
   실제로 거치는 지점에서 보완해야 학습 가능한 차이가 생긴다.
2. **얼마나 중요하냐보다 더 중요한 건 "무엇으로 보완하느냐"다** — 모든 결측
   사례에 동일한 고정값을 쓰는 것보다, 남아있는 다른 정보를 조건으로 사용해
   사례별로 다르게 보완하는 것이 훨씬 효과적이다. 이건 원 MPLMM 논문류가 실제로
   prompt를 조건부로 생성하는 이유이기도 하다 - 우리가 직접 실험으로 그 필요성을
   재발견한 셈이다.
3. 그럼에도 naive 대비 개선은 있지만 ceiling까지는 한참 못 미친다 — **결측된
   정보 자체를 완전히 복원할 수는 없고, 어느 정도만 보완 가능하다**는 현실적인
   한계도 동시에 보여준다. 이건 과장 없이 정직한 결론이라 오히려 신뢰도를 높여준다.
