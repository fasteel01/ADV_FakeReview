# 실험 D (진행 중): 실제 사람이 쓴 가짜 리뷰 + 실제 이미지 데이터셋 직접 구축

## 왜 필요한가

실험 A(AiGen-FoodReview)와 실험 C(Ott)를 비교해보니, 같은 파이프라인인데도
"가짜의 정체"에 따라 성능이 크게 갈렸다(acc 0.997 vs 0.879). 그런데 실험 C(Ott)는
텍스트만 있어서, "사람이 쓴 진짜로 어려운 가짜 리뷰"를 이미지까지 포함해서
검증한 적은 아직 없다. 그래서 "이미지 + 텍스트가 둘 다 있으면서 + 가짜가 LLM
대필이 아니라 실제 상황에서 나온 가짜"인 데이터셋을 찾아봤는데, 공개된 형태로는
존재하지 않는다는 걸 확인했다(AiGen-FoodReview 논문 저자들이 이 데이터셋을 만든
이유 자체가 이 갭 때문이었음).

## 접근 방법: 두 데이터셋을 조인해서 직접 만들기

기성 데이터셋이 없으니, 서로 다른 목적으로 만들어진 두 공개 데이터셋을 조인한다.

| | 내용 | 이미지 | 가짜 라벨 |
|---|---|---|---|
| Hollenbeck et al. `fake-reviews-data` | Amazon 가짜 리뷰 언더그라운드 마켓을 실제로 추적 + Amazon 자체 리뷰 삭제 데이터를 결합해 만든 (asin, reviewer, date) 단위 가짜/진짜 라벨 | 없음 | **있음 (실제 상황 기반)** |
| McAuley Lab Amazon Reviews 2023 (Health_and_Personal_Care) | 리뷰 텍스트 + 리뷰어 ID + 시각 | **있음 (실사용자 업로드 사진)** | 없음 |

asin(상품 ID) 기준으로 두 데이터를 조인해서, "실제 가짜 라벨이 있으면서 + 실제
사진도 있는" 교집합 리뷰만 뽑아내는 게 목표. Health_and_Personal_Care(건강기능식품/
퍼스널케어) 카테고리를 고른 이유는 (a) 33개 카테고리 중 상대적으로 작아서(약 49만
건, 다른 카테고리는 수천만 건) 학교 서버에서도 다루기 쉽고, (b) 건강기능식품류는
실제로 가짜 리뷰 문제가 잘 알려진 카테고리라 Hollenbeck 데이터의 가짜 라벨과 겹칠
가능성이 상대적으로 높기 때문이다.

## 현재 상태 (미확정 요소)

이건 확실히 잘 될 거라고 장담할 수 있는 작업이 아니라 시도해보는 실험이다. 아직
모르는 것들:

1. **정확한 컬럼명**: Hollenbeck 데이터셋의 실제 스키마(어떤 컬럼이 asin인지,
   가짜 여부가 단일 컬럼인지 여러 플래그의 조합인지)를 문서만으로는 확인 못
   했다. `README.rtf`가 같이 들어있으니 다운로드 후 직접 확인 필요.
2. **조인 성공률**: asin이 겹치는 리뷰가 실제로 몇 건이나 될지 모른다. 두
   데이터셋이 수집 시기/방식이 달라서 겹치는 게 거의 없을 수도 있다.
3. **이미지 첨부율**: Amazon 리뷰 중 실제로 사진이 첨부된 비율이 낮을 수 있어서,
   조인 후 "가짜 라벨 + 이미지" 둘 다 있는 최종 표본 수가 실험하기에 충분히
   클지 불확실하다.

그래서 `src/build_amazon_hard_dataset.py`를 두 단계로 나눴다: 먼저 `--explore`
모드로 실제 스키마와 조인 가능 건수를 확인하고, 그 결과를 보고 나서(다음 턴에)
실제 조인/라벨링/이미지 다운로드 로직을 확정한다. 잘못된 컬럼명을 추측해서
구현하면 조용히 틀린 라벨을 만들 위험이 있어서, 일부러 이 단계를
`NotImplementedError`로 막아뒀다.

## 실행 방법 (학교 서버/Colab, 샌드박스 아님)

`mcauleylab.ucsd.edu`(Amazon Reviews 2023 원본)와 `dropbox.com`(Hollenbeck 라벨
데이터)은 Claude 샌드박스 네트워크에서 막혀있어(403) 이 단계는 샌드박스에서
실행/검증할 수 없었다. 실험 A `--mode full`과 같은 이유로 학교 서버/Colab에서
진행한다.

```bash
bash scripts/download_amazon_hard.sh
python src/build_amazon_hard_dataset.py --explore
```

`--explore` 출력(컬럼 목록, dtype, 값 분포, asin 교집합 수)을 그대로 공유해주면
그걸 보고 조인 로직을 확정해서 업데이트해줄 예정.

## 리스크 및 대안

조인이 잘 안 되거나(표본이 너무 적거나) 라벨 신뢰도가 낮다고 판단되면, 이 실험은
발표에서 "시도했지만 실현 가능성 문제로 향후 연구로 남김"으로 정리하고, 기존
실험 A/B/C(난이도 스펙트럼: 쉬움-보통-어려움)만으로도 발표는 충분히 완결된다.
즉 이 실험은 성공하면 보너스고, 실패해도 기존 결과에 영향 없는 애드온이다.
